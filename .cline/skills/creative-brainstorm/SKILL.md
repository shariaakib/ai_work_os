# Creative Brainstorm

This project's north star (see `VISION.md`) is:

> From apps to outcomes. From software users to AI-assisted workers. From
> individual AI chats to an intelligent workplace.

Every idea generated by this skill should be checked against that north star:
does it reduce app-switching, help the AI understand relationships between work,
or move the user closer to just describing an outcome and getting it done?

## Process

1. **Clarify the creative target.** In one line, restate what we're brainstorming
   (a new agent? a Work Graph relation type? a UX flow? a feature name? a fix for
   a design problem?). If ambiguous, ask.
2. **Diverge first — quantity over judgment.** Generate at least 6-10 raw ideas
   before filtering anything out. Don't self-censor "boring" or "weird" ideas in
   this phase — write them all down.
3. **Converge.** From the raw list, pick the 2-4 most promising ideas. For each,
   give a one-line "why this fits the vision" and a one-line "concrete next step"
   (e.g. which file/class it would touch in this codebase).
4. **Offer a wildcard.** Include at least one unconventional/ambitious idea that
   goes beyond the immediate ask — something that stretches toward the
   Jarvis-like intelligent workplace vision, even if it's a bigger lift.

## Techniques to use

- **Analogy thinking**: "What would a human executive assistant/analyst/developer
  do here that this codebase doesn't yet model?"
- **Reverse brainstorming**: "How would this feature fail, annoy, or feel
  intrusive to the user?" — then flip each failure into a design idea (this is
  especially useful for permission/approval UX, since nagging the user breaks
  trust — see `VISION.md`'s "Trust is part of the product" section).
- **Combination**: mix two existing capabilities together (e.g. what happens if
  the Research Agent's findings feed directly into the Work Graph as nodes?).
- **"Yes, and"**: build directly on the user's own half-formed idea rather than
  replacing it.

## Project-specific idea prompts

Use these as starting points when the user doesn't have a specific target yet:

- **New specialist agents** beyond the current five (`ResearchAgent`,
  `AnalystAgent`, `WriterAgent`, `DeveloperAgent`, `ExecutiveAssistantAgent` in
  `src/agents/specialist_agents.py`). `VISION.md` explicitly lists candidates:
  Finance, Marketing, HR, Sales, Legal-support, Operations. What would each
  agent's unique `capabilities` list look like?
- **New Work Graph relation types** beyond `manages`, `belongs_to`, `related_to`,
  `requires`, `deadline` (see `src/core/work_graph.py`). E.g. `blocks`,
  `mentors`, `reports_to`, `depends_on`, `escalates_to`.
- **New memory categories** beyond `preference`/`fact`/`rule`/`context` (see
  `src/core/memory.py`) — what other kinds of workplace knowledge should the AI
  retain?
- **Permission/trust UX ideas** — creative ways to make the Safe/Approval/
  High-risk system (`src/permissions/permission_manager.py`) feel transparent
  and trustworthy rather than like friction.
- **Naming ideas** — for new agents, features, or the product itself, following
  the existing tone (short, evocative, work-themed: "Work Graph", "AI Manager").

## Output format

Present ideas as a numbered list. For the converged top picks, use this format:

```
1. **Idea name** — one-line description
   - Why it fits the vision: ...
   - Concrete next step: e.g. "Add `LegalSupportAgent` class to
     src/agents/specialist_agents.py with capabilities [...]"
```

Keep the tone energetic and exploratory during divergence, then get concrete and
actionable during convergence — the goal is ideas the user can actually act on in
this codebase, not abstract inspiration.
